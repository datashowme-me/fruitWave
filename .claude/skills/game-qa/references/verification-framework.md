# 真机验证框架(M1)

判据文件:`Docs/M1-Verification.md`。所有"完成"声明必须落到该文件的表格行。

## 表格与填写要求

- **构建与设备**:构建版本 / Git commit、TV 型号 / tvOS、iPhone 型号 / iOS、
  实际视频尺寸 / 帧间隔、光线 / 距离。
- **连接(每组 ≥10 次)**:冷启动、中断重连、取消选择、权限拒绝、退出无残留采集。
- **延迟与吞吐**:推理/排队/场景消费 P50/P95;外部端到端至少 120fps 相机 + 30 次动作,
  报告中位数、P95、样本数与 ±1 拍摄帧不确定性。
- **准确性与安全**:预设穿越 ≥50、慢移/静止/遮挡对照 ≥50、断连恢复等;
  漏切率/误切率定义见 M1 文件;跨失效区间连线、错误接管、重复计分为阻断缺陷。
- **稳定性**:两个 TV 代际 × ≥2 款 iPhone,每组连续运行 60 分钟。
- **冻结记录**:指标定义、阈值、设备、场景、测量方式、样本量、理由、负责人、日期、
  构建版本,由产品与开发负责人共同填写。

## 证据归档

- 目录:`Docs/Evidence/`。
- 命名:`deploy-<时间戳>.log`(部署)、`FruitWaveDiagnostics-<时间戳>.json`(诊断快照)。
- 每条实测值注明设备、系统、构建、样本量、测量方式。

## 红线

- 编译通过 / 模拟器通过 / 单测通过都不是"真机完成"。
- 相机通信与交互延迟不真机测量不得下结论。
- 自动化证据(引擎模拟 100 局等)不能替代真机验收。
